# 作り方

Claude Code の相棒キャラを決めて、絵を作り、Claude Desktop の Code タブに出すまでの記録です。2026年10月の Claude Code 2.1.289 で作りました。

## 1. キャラの話し方を決める

先に、Claude にどう話してほしいかを `~/.claude/CLAUDE.md` に書きました。何度か試して、次のことが分かりました。

- 語尾を変えるだけでは、普段の Claude とほとんど変わらない。後輩キャラの「〜です！」は、もともとの丁寧語と同じに見える
- 好きなキャラ（艦これの大鯨・龍鳳、アークナイツのサイレンス、ホルハイヤ、アーミヤ）を調べて並べると、「有能で落ち着いているが、相手にだけ見せる顔がある」という共通点があった。そこから「真面目な研究者肌の相棒で、相手を気遣う」キャラにした
- 報告の本文までキャラで書くと読みにくい。本文は淡々と書き、感情は最後のひとことに集めると、読みやすさとキャラの両方が保てる

最終的な書き方は [examples/CLAUDE.md-snippet.md](../examples/CLAUDE.md-snippet.md) にあります。

## 2. キャラデザインを作る

Magnific（Seedream 5 Pro、1枚 100 クレジット）で作りました。

1. 方向性の違う4案を作る（研究者、気遣いのお姉さん、オペレーター、エンジニア）
2. 気に入った研究者案を参照画像に入れて、色違いを4つ作る。参照を入れると、顔とポーズを保ったまま色だけ変えられる
3. 決まった案（銀髪ボブに毛先のテラコッタ、銅色の眼鏡、白衣）を参照に入れて、ちびキャラを作る

ちびキャラのプロンプトでは、あとでベクター化しやすいように次のことを指定しました。

- flat colors only, no gradients
- bold clean dark outlines
- pure white background

## 3. 表情とポーズの差分を作る

ちびキャラの絵を参照に入れて「同じキャラ、同じ服、同じ画風で、表情だけ変える」と指示すると、ポーズまでぴったり揃った差分ができました。

ただ、帯の中では 72px ほどに縮むので、**顔の中だけの違いは見分けられません**。ポーズも変えて、形で区別できるようにしました。

| 表情 | ポーズ |
|---|---|
| ふつう | タブレットを持って立つ |
| うれしい | タブレットを頭の上に掲げてバンザイ、キラキラ |
| 心配 | タブレットを胸に抱えて、首をかしげる |
| 困った | 片手で頭をかく、大きな汗のしずく |
| 真剣 | 人差し指で眼鏡を上げる |

## 4. SVG にする

Claude Desktop の Code タブで mod が使える絵の要素は `Svg` だけです（PNG を出す `Image` はターミナル専用）。そのため、絵をベクターに変換しました。

1. Magnific の images_to_svg で変換する（1枚 150 クレジット）
2. 変換結果は 16 万〜21 万文字あり、`Svg` の上限 131,072 文字を超える。`tools/optimize-svg.mjs` で縮める
   - 座標を整数に丸め、viewBox を半分（1024×1024）にする
   - `transform="translate(0,0)"` など意味のない記述を消す
   - `rgb(...)` を `#rrggbb` にする
   - 背景の白い全面矩形を消して、透明にする
3. 縮めると 8 万〜10 万文字になる。ヘッドレスの Chrome で暗い背景と明るい背景に描き、崩れや白い塊が残っていないか確かめる

## 5. mod を書く

mod の書き方は、Claude Code に入っている plugin-authoring スキルに従いました。使ったのは次の仕組みです。

| 仕組み | 使い方 |
|---|---|
| `ui.render` の `AbovePrompt` | 入力欄の上の帯を描く。`e.surface` が `desktop` なら `Svg` と吹き出し、それ以外は文字だけ |
| `turn.complete` | 返答が終わったとき。`e.answer` から最後の段落を取り出して吹き出しに入れ、表情を決める |
| `tool.call` | ツールが呼ばれたとき。ツール名から「書いてます…」などの一言を決める |
| `prompt.submit` | 入力を送ったとき。「考えてます…」にする |
| `atom` / `read` / `update` | 吹き出しの文、作業中の一言、表情を持つ。値を変えると帯が描き直される |

吹き出しに出す文は、返答の最後の段落です。表、箇条書き、コード、出典は飛ばし、「？」で終わる確認の質問も出しません。60 文字を超えたら切ります。

## 6. つまずいたところ

### session の途中で読み込んだ mod が Desktop に出ない

ホットリロードで session の途中に mod を読み込んだところ、帯も toast も出ませんでした。mod 自身にファイルへ記録を書かせて調べると、次のことが分かりました。

- `session.start` は呼ばれていて、mod は動いていた
- `ui.render` の `AbovePrompt` が一度も呼ばれていなかった
- `$.session.surfaces()` が `[]` で、描画する画面が1つもつながっていなかった

`settings.json` の `env` に `CLAUDE_CODE_PLUGIN_DIRS` を書いて、**新しい session を開く**と、`surface=desktop` で描画が呼ばれて表示されました。

### `$` を関数に渡すと読み込みに失敗する

`$`（エンジンの interface）を関数に渡すときは、その関数をファイルの一番外側に `function` で宣言する必要があります。`register` の中で `const log = async ($, text) => ...` と書くと、読み込みの検証で止まります。

### 状態の型定義は1ファイルで完結させる

`$.state` に置く値の型（`types/index.d.ts` の `PluginState`）から、別ファイルの型を import すると、`claude plugin validate` が「宣言されていない」と判定しました。表情の種類は型定義のファイルに直接書きます。

### テストではイベントの終端を自分で用意する

`claude plugin test` の中で `$.turn.complete(...)` を呼ぶと、「その下で答えるものがない」と失敗します。テスト側で `on('turn.complete', async () => ({ text: '' }))` を登録しておきます。テスト環境ではファイルの読み書きや `$.session.surfaces()` も使えないので、記録のような補助の処理は失敗しても止まらないようにしておきます。

| デザイン案 4枚、色違い 4枚、ちびキャラ 1枚 | 900 |

顔だけの差分は小さいと見分けられず使わなかったので、最初からポーズ差分を作れば 1,000 クレジット少なく済みます。
